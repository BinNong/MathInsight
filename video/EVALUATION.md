# Evaluator · 视频质量评估规范

> Evaluator 是视频上线前的**独立质检角色**，与生成模块解耦。
> 它只做判断，不修改内容；不通过则返回结构化返修单，生成模块据此重做。
> **未经 Evaluator PASS 的视频禁止上线。**

---

## 0. 两层评估

| 层 | 执行者 | 内容 | 判定 |
|---|---|---|---|
| **自动层** | `scripts/evaluate_video.py` | 时长/流/编码/音量/黑帧；静帧像素级安全区与亮度 | 客观 PASS/FAIL，FAIL 直接拦截 |
| **AI 层** | 自动化里的 Evaluator 角色 | 逐张看静帧，按第 2 节评分表打分项 | 总分 + 红线项，见第 3 节 |

两层都 PASS 才算最终 PASS。自动层 FAIL 时不必做 AI 层，直接返修。

---

## 1. Evaluator 的输入

1. MP4 成片
2. `video/out/check-<id>/` 下**全部场景静帧**（生成模块产出，命名 = scene.kind）
3. `script.json`（场景时间轴、公式、旁白词级时间戳）
4. 热点 JSON 原文（核对内容忠实度）

Evaluator 按顺序执行：
```bash
# ① 自动层
python3 video/scripts/evaluate_video.py <mp4> --script video/src/script.json \
  --stills-dir video/out/check-<id> --out video/out/eval-<id>.json
```
若返回非 0 或报告 `decision=FAIL` → 直接出返修单，跳过 AI 层。

---

## 2. AI 层评分表（总分 100）

对每张静帧逐项观察；一个项目在所有相关帧上都合格才给满分，任一帧不合格按"该项最低分"计。

### A. 内容忠实度（25 分）
- [ ] 标题/正文/公式与热点原文一致，**没有编造事实或数字**（*红线项*）
- [ ] 数值与原文实算结果一致；示意数据有标注
- [ ] 场景顺序符合叙事逻辑（现象→数学→推导→结论→思考）
- [ ] 无画廊禁区内容（政治/争议/宗教/色情暴力/投资医疗建议）（*红线项*）

评分：红线任一违反 = 0 分并直接 FAIL；其余按完整度 25/18/10/0。

### B. 排版与可读性（25 分）
- [ ] **公式完整显示**：无右侧溢出、无被裁切下半行（*红线项*）
- [ ] 文字不超时/卡边：距画面边缘 ≥ 36px 安全区
- [ ] 无文字与字幕/其他文字重叠
- [ ] **画面正文不与底部字幕重复同一句**（*红线项*）——两处内容来自同一 captions 数组，容易出现"同一句话出现两次"；专属场景（orbit/cosmic-intro 等）应只放物体+标题，正文交给字幕条
- [ ] 中文无方块字/乱码；KaTeX 公式符号正确
- [ ] 字号适中：正文可读，公式在卡片内饱满

评分：红线违反 = 0 分并直接 FAIL；其余按问题帧数 25/18/10/0。

### C. 视觉呈现（25 分）
- [ ] 画面有**具象物体**，不是纯文字+线条（*红线项*，用户反复强调）
- [ ] 物体有体积感：球面光照/阴影/辉光/自转纹理，不是纯色圆点
- [ ] 主体足够大、占画面有存在感（张扬，不藏着掖着）
- [ ] 专属场景正确：天文=星球/轨道/光谱，同步=振子收敛，幂律=举重等
- [ ] 背景有动感但不抢字（流场/星场/粒子），阅读区亮度被压低

评分：红线违反 = 0 分并直接 FAIL；其余按完成度 25/18/10/0。

### D. 音画同步与节奏（25 分）
- [ ] 字幕逐词高亮与旁白同步（抽查 2 个相邻帧，高亮词应不同）
- [ ] 画面关键词高亮落在词被读到时
- [ ] 场景切换与音乐 impact 同帧；无"声画错半拍"
- [ ] 无异常黑屏、无突然静音段（自动层已查）
- [ ] 片头片尾完整，无硬切断裂

评分：按问题严重程度 25/18/10/0。

---

## 3. 判定规则

```
PASS  = 自动层 PASS 且 AI 层总分 >= 80 且无任一红线项违反 且每项 >= 15
FAIL  = 自动层 FAIL，或总分 < 80，或任一红线项违反，或任一项 < 15
```

**红线项一票否决**（即使总分够）：
- 内容编造/合规禁区
- 公式溢出被裁
- 画面没有具象物体（只有文字）

## 4. 返修单格式（FAIL 时必须输出）

Evaluator 不通过时，输出结构化返修单，供生成模块精确修复：

```json
{
  "decision": "FAIL",
  "score": 67,
  "layers": {
    "automated": {"decision": "PASS", "report": "video/out/eval-<id>.json"},
    "ai": {"A": 25, "B": 10, "C": 10, "D": 22}
  },
  "red_lines": ["B: 公式帧 formula.png 右侧被裁，缺失质量反推项"],
  "issues": [
    {
      "category": "B-排版",
      "frame": "formula.png",
      "severity": "blocker",
      "observation": "公式第二行下半被卡片底部裁掉",
      "fix": "Scene.tsx 公式卡片去掉固定高度/overflow:hidden，行高改 1.15"
    },
    {
      "category": "C-视觉",
      "frame": "hook.png",
      "severity": "major",
      "observation": "开场只有标题文字，没有具象物体",
      "fix": "build_video.py 题材关键词命中后插入专属场景；Scene.tsx 加大 StarBall 半径"
    }
  ],
  "retry_hint": "修 B/C 两类后重跑 bash video/scripts/generate_video.sh <id> --stills-only，再看静帧复核"
}
```

`fix` 字段必须**具体到文件和改法**，不能写"优化一下""再好看点"这类空话。

---

## 5. 返修闭环

```
生成 → 自动评估 → AI 评估 → PASS → 上线（上传+登记 video 字段）
              ↓ FAIL
         返修单 → 生成模块按 fix 修改 → 重渲染静帧 → 再评估
              ↓ 最多 3 轮
         仍 FAIL → 停线，汇报管理员，绝不带病上线
```

- 每轮返修只针对返修单里的问题，不要推倒重来
- 3 轮仍不通过：停止，输出完整返修单与失败原因，交人工介入
- 通过后才允许调用上传与 `POST /api/hotspots/admin/video` 登记

## 6. 已知误判提醒（Evaluator 必读）

- **场景开头 0–0.18s 的冲击波/粒子爆发会短暂盖住公式**——这是刻意的 BeatFX 转场，不是排版 bug。检查公式请用静帧目录里的 `formula.png`（脚本已自动选在冲击波之后的稳定帧）
- **深空主题背景本身偏暗**（平均亮度 18–42），不是黑屏；只有平均亮度 < 12 才算异常
- **星点出现在边缘**是正常背景；只有"连续大面积高亮块贴边"才算文字溢出（自动层用 >190 亮度占比判定）
- **正文与字幕内容相似**不是 bug——画面正文是强调、字幕条是完整讲解；只有**位置重叠**才算问题（公式场景已刻意不放正文避免此问题）
